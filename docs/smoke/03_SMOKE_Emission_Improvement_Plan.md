# 배출량 개선 계획

> **문서 순서:** 앞선 [02 기존 체계 분석](02_Legacy_SMOKE27_Emission_Processing.md)을 근거로 개선 원칙을 정리한 문서입니다. 실제 국내 입력 생성·검증은 [04 국내 가이드](04_SMOKE_Busan_Case_Run_Guide.md), 국외 HTAP_v3.2 입력 생성·검증은 [05 국외 가이드](05_HTAP_v32_Reproduction_Checklist.md)를 따르세요.

> **목표:** 최신 프로그램(WRF 4.5.1 · SMOKE 5.3 · CMAQ 5.5)으로 부산 대기질 모델링 시스템을 교체하면서, 배출량(국내·국외)을 기존 체계에 쓰인 자료(CAPSS 2017 등)보다 최근 자료로 교체하고, 종분배·공간·시간 프로파일 등 개선할 수 있는 입력은 최신 자료로 개선한 새 배출량 체계를 만든다.
> **작성:** 2026-10-22. 이 문서는 **계획과 결정 사항**을 정리한다. 실제 SMOKE 실행 기록은 [CAPSS 2023 기준 부산 사례 실행 가이드](04_SMOKE_Busan_Case_Run_Guide.md)에 국내 점 A단계부터 남긴다.
> **검증 근거:** 사용자 제공 자료(CAPSS 2017·2023 1km 격자 배출량과 코드리스트·파일설명, 기존 운영체계 SMOKE 2.7 입력 파일, L-NEAS SMOKE 구동 매뉴얼 v1.0.1)를 작성 환경에서 직접 열어 확인했다. 2026-10-22 계획 작성 당시에는 새 체계 배출량을 아직 SMOKE로 실행하지 않았다. **2026-10-30 갱신:** 국내 CAPSS 2023 점·면·이동·바다 4개 부문 × 27·09·03·01KM 완료(사용자 제공 2026-10-23~29 Linux 실행 기록 기준). 점 인벤토리 보고서 합계와 면·이동·바다 NOx 격자 합계 일치. 다음은 국외(HTAP_v3.2)·생물성·병합 및 CMAQ 연계 검증. **2026-11-11 갱신:** 국외 HTAP_v3.2 27·09·03KM의 8개 묶음 처리가 완료되었으며 01KM은 제공된 시험 결과에서 영역 내 국외 배출량 0으로 제외한다(05 §8.4 재현성 확인 기준 참고). 생물성·병합·CMAQ는 미실행. **2026-11-11 생물성 결정:** 기존 체계(27·9km MEGAN v2.04, 3·1km BEIS 3.12)를 확인했고, 새 체계는 SMOKE 생물성 부문 없이 **CMAQ 5.5 CCTM 인라인 MEGAN 3.2를 4개 도메인에 공통 적용, 토양 NO는 YL95**로 확정했다(§9). **2026-11-05 갱신:** 사용자 보고에 따르면 다른 시스템에서 저장소 문서를 따라 국내 배출량 처리를 재현했다. 이번 문서 갱신에서는 해당 시스템의 환경정보·실행 로그·NetCDF를 독립 확인하지 않았으며, 설치부터 전체 재구축했는지와 재현한 날짜·도메인 범위는 실행 기록에 명시할 사항이다. CMAQ 연계 검증은 별도이다. 입력 자료별 최신화 상태와 추가 업그레이드 계획을 §7에 정리. 이번 GitHub 등록 과정에서 그 원자료나 모델을 별도 재검증·재실행하지 않았다.

## 4. 확인된 사실과 결정 사항

### 4.1 CAPSS 1km 격자 원자료 형식

| 항목 | 내용 |
|---|---|
| 파일 | 점오염원 `지역+p.txt`, 면 `지역+a.txt`, 이동 `지역+m.txt`, 점오염원 식별(사업장명·TMS) 별도. 쉼표 구분, 머리줄 있음 |
| 점오염원 열 | `INVEST_YEAR, ADMIN_CD, POINT_ID, SCC_CD, FUEL_CD, TM_X, TM_Y, ALTITUDE, STACK_HEIGHT(m), STACK_DIAMETER(m), GAS_TEMPER(℃), GAS_SPEED(m/s), CO, NOx, SOx, TSP, PM-10, VOC, NH3, PM-2.5` |
| 면·이동 열 | `INVEST_YEAR, ADMIN_CD, TM_X, TM_Y, ALTITUDE, SCC_CD, FUEL_CD,` 오염물질 8종 |
| 단위 | **kg/yr** (metric) |
| 좌표 | TM km. Bessel 1841, Tokyo 측지계, 중부원점(경도 127°00′10.405″, 위도 38°), False Easting 200,000 m, False Northing 500,000 m. 면 자료는 격자 왼쪽 아래 기준. 2019년 자료부터 경위도판(격자 중심)도 제공 |
| 코드 | 시군구 10자리(2023) / 5자리(2017), SCC 8자리, 연료 5자리 |
| 바다 | 2014년 자료부터 포함. 2023 지역 코드 `9010000000`(바다), 선박 SCC `0803…` |

2023 원자료는 기존 체계의 해상 전용 SCC(`98…`)를 쓰지 않고 **바다 지역 코드로 구분**한다.

TM → 위경도 변환식(pyproj):

```text
+proj=tmerc +lat_0=38 +lon_0=127.002890277778 +k=1 +x_0=200000 +y_0=500000 +ellps=bessel
+towgs84=-115.80,474.99,674.11,1.16,-2.31,-1.63,6.43 +units=m +no_defs
```

확인: 2023 점오염원 첫 레코드(서울 종로구, TM 197.103, 451.813 km) → 126.968°E, 37.569°N.

### 4.2 단위: kg/yr → short ton/yr

SMOKE는 인벤토리의 ton을 short ton(907.18474 kg)으로 처리한다. 2017 원자료(kg/yr)와 기존 IDA 점오염원 값을 비교하면 비율 중앙값이 **907.19**로, 기존 IDA는 `kg ÷ 907.18` short ton으로 정확히 변환되어 있었다. 새 체계도 **kg ÷ 907.18474**로 변환한다(L-NEAS 매뉴얼 p.14의 short ton 변환과 같음).

### 4.3 SCC 10자리 체계와 기존 연료 번호

기존 체계와 L-NEAS는 SCC 8자리 뒤에 연료(이동오염원은 도로+연료) 2자리를 붙인 10자리를 쓴다. 시간·종분배 참조가 10자리 SCC 기준이므로 2023 원자료(연료 5자리)를 같은 10자리로 바꿔야 기존 참조를 이어 쓸 수 있다.

기존 체계의 2자리 연료 번호는 CAPSS 코드리스트에 없는 **기존 체계 고유 번호**다(2017 원자료도 연료 5자리). 2017 원자료 점오염원과 기존 IDA 점오염원을 배출량 값으로 짝지어(2,142쌍) 규칙을 찾았다.

> **2자리 번호 = 2017 연료 코드표에서 대분류 줄(코드 끝 `00`)을 뺀 순번.** 예외: `20500`(등유) → `44`, `999xx`(기타 전부) → `99`.

| 2자리 | 연료 | 2자리 | 연료 |
|---|---|---|---|
| 02 | 비민수용무연탄 10102 | 36·37·39 | 경유 1.0%·0.4%·0.1% |
| 07 | 유연탄 10201 | 44 | 등유 20500 |
| 19·20 | B-A유 0.5%·0.3% | 45 | 보일러등유 20502 |
| 28~33 | B-C유 4.0%~0.3% | 80 | 프로판 40101 |
| 82 | LNG 40201 | 99 | 기타 999xx |

짝지어진 모든 연료에서 규칙과 어긋나는 경우가 없었다. L-NEAS 매뉴얼 붙임 1의 연료 2자리(예: 유연탄 `81`, LNG `41`)는 **다른 체계**이므로 섞어 쓰지 않는다.

**현재 생성기에서 별도 번호를 부여하는 연료 9종**은 새 코드를 붙이고, 참조는 성질이 가까운 연료에서 빌린다.

| 연료 | 새 코드 | 참조를 빌릴 연료 |
|---|---|---|
| 정유가스 23101 | G1 | LNG 82 |
| 고로가스 50101 / 전로가스 50102 / 코크스가스 50103 | G2 / G3 / G4 | LNG 82 |
| 소화가스 50201 / 매립가스 50202 | G5 / G6 | LNG 82 |
| SRF 80201 / BIO-SRF 80202 | S1 / S2 | 유연탄 07 |
| CNG 41300 | C1 | LNG 82 |

영문이 들어간 SCC를 SMOKE 5.3이 읽는지는 첫 실행에서 확인한다. 문제가 있으면 쓰이지 않는 숫자 번호로 바꾼다.

### 4.4 시간·종분배 참조 보완 규칙

| 순서 | 규칙 |
|---|---|
| 1 | 기존 10자리 SCC 참조와 정확히 일치 |
| 2 | 새 연료는 빌린 연료 번호로 일치 |
| 3 | 같은 SCC8·같은 연료 분류(연료 5자리의 앞 3자리) 참조. 새 연료는 빌린 연료의 분류를 쓰고, 2자리 연료 번호가 가까운 참조를 우선 |
| 4 | 같은 SCC8의 다른 연료 참조: 82 → 99 → 80 → 33, 없으면 SCC10 정렬 첫 항목 |
| 5 | 같은 SCC6 참조: 빌린 연료 번호 → 82 → 99, 없으면 SCC10 정렬 첫 항목 |
| 6 | SMOKE 기본 프로파일 |

위 규칙은 현재 [생성기](files/busan/2023capss/generators/make_busan_2023_domestic_inputs.py)의 `source()`와 대응한다. 빌린 참조는 모두 출처를 기록한다(`scc10_reference_map`). 다음 수치는 기존 점 실행 기록이며, 같은 SCC 항목의 세부 단계별 분류는 생성된 매핑 파일을 확인한다. 2023 점오염원 적용 결과: 조합 269개 중 정확 일치 178, 빌린 연료 25, 같은 SCC 55, 기본값 11. 배출량 기준 NOx 99.8%, VOC 99.99%가 기존 참조 또는 빌린 참조를 받는다.

### 4.5 점오염원 굴뚝 제원 보완 규칙

결측(빈칸)과 0 이하 값을 결측으로 보고 차례로 채운다. 채운 내역은 기록 파일로 남긴다.

| 순서 | 규칙 |
|---|---|
| 0 | 같은 굴뚝(`POINT_ID`)의 다른 줄 값 |
| 1 | 같은 SCC·연료 굴뚝들의 중앙값 |
| 2 | 같은 SCC 중앙값 |
| 3 | 전체 중앙값 |

2023 점오염원(14,437줄): 온도 결측 1,660, 속도 결측 1,841, 높이 0 이하 220, 내경 0 이하 225. 거의 모두 1번 규칙으로 채워진다. 같은 지역·굴뚝·SCC·연료의 중복 148줄은 합친다.

### 4.8 공간배분 (계획)

CAPSS 2023 1km 격자 배출량에서 **시군구 안의 SCC별(필요 시 SCC10별) 격자 분포**를 뽑아 4개 도메인 격자로 옮겨 대리자료를 만든다. 기존 체계 대리자료도 같은 원리(CAPSS 격자 분포, 시군구별 합계 1)였으므로 방법은 유지하고 자료만 2023으로 바꾼다.

- 바다(`90100`)도 같은 방법으로 4개 도메인 모두 만든다 → 기존 3·1km 해상 대리자료 부재 문제 해결
- 시군구 경계를 넘는 몫(영역 밖)은 기존처럼 버려진다
- 대리자료 형식: SMOKE 표준(`#GRID` 머리말 + `번호 지역 열 행 비율`). 기존 조각 파일 규칙은 따르지 않아도 됨

## 5. 진행 방식

자료를 미리 다 만들어 두지 않고, **SMOKE를 부문별·단계별로 실제로 돌리면서 그 단계의 입력만 점검하고 보완한다.**

### 5.1 단계마다 하는 일

| 순서 | 내용 |
|---|---|
| ① 설명 | 이 단계에서 도는 프로그램과 하는 일 |
| ② 입력 점검표 | 이 단계가 읽는 파일만: 기존 그대로 / 개선 / 신규와 이유 |
| ③ 보완 | 개선·신규 파일만 이 자리에서 생성 (생성기와 함께 저장소 보관) |
| ④ 실행·확인 | 로그와 결과 합계 확인 |
| ⑤ 기록 | 실행 가이드에 단계 추가, 이 문서 §2 상태 갱신 |

### 5.2 SMOKE 단계

| 단계 | 프로그램 | 점검할 입력 |
|---|---|---|
| A | Smkinven | FF10 인벤토리, INVTABLE, 코드표 |
| B | Spcmat | 종분배 참조·프로파일·변환계수 |
| C | Grdmat | GRIDDESC, 대리자료 설명·참조·대리자료 |
| D | Temporal | 시간 참조·프로파일, 공휴일, 날짜 |
| E | Smkmerge (점오염원은 굴뚝 처리 포함) | 기상(MCIP) |
| F | Smkreport | 보고서 설정 → 원자료 합계와 비교 |

### 5.3 부문 순서

| 순서 | 부문 | 핵심 개선 |
|---|---|---|
| 1 | 국내 점 | CAPSS 2023, 굴뚝 보완, SCC10 참조 연결 |
| 2 | 국내 면·이동·바다 | CAPSS 2023, 1km 격자 기반 대리자료(바다 포함) |
| 3 | 국외 | HTAP_v3.2, 남한 제외 |
| 4 | 생물성 | SMOKE 부문 없음. CMAQ 인라인 MEGAN 3.2(§9) |
| 5 | 병합 | 국내+국외 인위 배출 → CMAQ 5.5 입력 |

각 부문은 09km로 먼저 통과시킨 뒤 27·03·01km로 넓힌다.

### 5.4 검증

L-NEAS 방식처럼 Smkreport 보고서(시도·시군구·SCC·시군구×SCC)를 원자료(kg → short ton 환산) 합계와 비교한다. 도메인 경계 밖 몫은 따로 계산해 차이를 설명한다.

| 2 | 도로이동 시간배분 | 평일·주말이 같은 프로파일이 많음 | 시간별 교통량 조사 자료(국토교통부·한국도로공사) → 차종·도로별 요일·시간 패턴 | 큼. NOx·VOC 일변화, 출퇴근 피크 |
| 3 | VOC 종분배 연결 (`gsref`) | 2020년 이전 연결, 국내 업종 특성 반영 부족 | 국내 VOC 종분배 연구 프로파일(국립환경과학원 등), L-NEAS 사용 프로파일, EPA 최신 플랫폼의 SCC–프로파일 연결 | 중~큼. 오존·2차 유기에어로졸 생성 |
| 4 | 농업 NH3 시간배분 | 월 고정 프로파일 | 기상 연동 시간배분 검토. CMAQ 양방향 NH3는 별도 배출·침적 교환 설정으로 검토 | 중. PM2.5 질산·암모늄 |
| 5 | 선박 시간배분 | 고정 프로파일 | 선박 AIS 운항 자료 | 중. 부산항 영향 |
| 6 | PM2.5 종분배 연결 | 기존 연결 | 업종별 국내 PM 성분 측정 자료 | 중 |

효과 크기는 검증 전 예상이며 개선을 보장하지 않는다. CMAQ 양방향 NH3는 단순 시간 프로파일 교체가 아니다. 토양·비료 관련 입력과 배출·침적 설정, 기존 비료 NH3와의 중복 계상 방지를 별도로 확인한다([공식 예제](https://usepa.github.io/CMAQ/DOCS/Users_Guide/Tutorials/CMAQ_UG_tutorial_benchmark_cracmm2_stage.html)).

자료 확보 가능성은 아직 확인하지 않았다. 1~3순위 원자료(굴뚝 TMS 시간별 자료, 시간별 교통량, 국내 VOC 프로파일)를 먼저 확보 가능한지 확인한다. 확보 후 접근·이용 조건, 적용 연도, 결측·이상치, 대상 오염물질, 사업장·도로와 SCC의 대응 및 연간 총량 보존 방법을 점검한다.

### 7.3 먼저 정할 것: CMAQ 5.5 화학 메커니즘

종분배 비율(`gspro`, `gscnv`)은 CMAQ 화학 메커니즘에 맞춰야 한다. 현재는 `CB6R3_AE7`이며, CMAQ 5.5는 CB6R5·CRACMM 등 더 새로운 메커니즘도 지원한다. **병합·CMAQ 기준 실행 전에 기준 메커니즘을 확정**한다. 메커니즘 변경 시 해당 메커니즘용 종분배 자료뿐 아니라 CMAQ 빌드 설정, 배출종 이름·단위·변환계수, 제어 파일과 입력 대응을 함께 확인한다. CMAQ 5.5 지원 메커니즘은 [공식 FAQ](https://github.com/USEPA/CMAQ/blob/main/DOCS/Release_FAQ/CMAQv5.5-Series-FAQ.md)를 참고한다.

**CMAQ 5.5 소스·메커니즘 재현 기준(사용자 제공 점검 기록):** 설치된 소스 `src/CMAQ_REPO` 커밋 `e10d0a0`(2025-07-11), 태그 `CMAQv5.5.0.3_11Jul2025`를 기준으로 한다. 새 시스템에서 `main`을 그대로 받지 말고 해당 버전 태그를 고정한다. **화학 메커니즘은 `cb6r5_ae7_aq` 잠정 후보**이며 병합 전에 확정해야 한다. 제공된 DESID 파일 비교에서는 `cb6r3_ae7_aq` 108행, `cb6r5_ae7_aq` 109행으로 `DMS` 항목이 추가된 차이가 보고되었으나, 실제 SMOKE 출력 배출종과의 대조는 아직 수행하지 않았다.
### 7.4 진행 순서

| 단계 | 할 일 |
|---|---|
| 1 | CMAQ 5.5 기준 메커니즘 확정, 현재 배출종·단위·종분배 자료와 CMAQ 입력 대응 확인 (§7.3) |
| 2 | 완료된 국외(HTAP_v3.2) 산출물을 사용해 확정한 메커니즘에 맞춰 병합·CMAQ 실행(생물성은 인라인 MEGAN 3.2, §9) → **기준 결과** 확보 |
| 3 | 1~3순위를 하나씩 교체하고, 교체마다 기준 결과와 배출량·농도 차이를 비교해 효과를 기록 |
| 4 | 4~6순위는 자료 확보 상황에 따라 검토 |

교체한 입력은 04 실행 가이드의 해당 부문 입력 표(의미·출처)와 생성기에 반영해 재현 가능하게 유지한다.


## 8. 2026-11-10 국외배출량 적용 및 재현성 기록

국외 배출량은 계획 단계의 HTAP v3.1이 아니라 **HTAP_v3.2(2020년, 0.1°)**를 적용한 것으로 갱신한다. 27·09·03KM 각 8개 묶음 SMOKE 실행을 완료했다는 2026-11-10~11 사용자 제공 기록을 기준으로 한다. **03KM 포함, 01KM 국외 배출 0으로 제외**하며, 새 시스템에서는 [05 국외 처리 가이드](05_HTAP_v32_Reproduction_Checklist.md) §8.4의 파일 존재·전 물질 배출량 확인 조건을 따른다. 국내 입력은 [04 국내 가이드](04_SMOKE_Busan_Case_Run_Guide.md)를 따른다.

- 남한 중복 제거는 CAPSS 1km 셀이 닿는 HTAP 0.1° 셀 전체를 0으로 만들기 때문에 해안·접경의 국외 배출량 일부도 손실될 수 있다.
- BC·OC가 PM2.5를 초과한 셀의 성분 비례 축소는 PM2.5 질량을 보존하지만 BC·OC의 원자료 성분 질량을 변경한다.
- 일부 하위 부문 프로파일은 기존 상위 부문을 대체 적용한 잠정 매핑이다.
- 국내·국외 병합, CMAQ-ready 최종 입력, MEGAN 입력 생성 및 CCTM 실행은 미완료다.

## 9. 생물성(식생) 배출량 처리 방식 결정 (2026-11-11)

> **상태:** 방식 결정 완료. MEGAN 전처리기 설치·입력 생성과 CCTM 실행은 **미실행**(CCTM 단계에서 진행). 아래 기존 체계 내용은 사용자 제공 자료를 작성 환경에서 직접 열어 확인한 범위이며, 기존 모델을 재실행하지 않았다.

### 9.1 기존 운영체계의 생물성 처리 (확인 결과)

| 도메인 | 모델 | 입력 자료 | 처리 흐름 |
|---|---|---|---|
| 27·9km (동아시아·한반도) | MEGAN v2.04 (`MGNHOME=.../megan/MEGANv2.04`) | 식생유형 PFT 4종(활엽수·침엽수·관목·초본, MODIS MCD12Q1, `PFT_MODIS2013_*`), 월별 LAI(MODIS MCD15A2, `LAI_MODIS2015_*_EF1`), 배출계수 EF | MCIP `METCRO2D` → `megan` → `mg2mech`(CB05) → `b3gts_l.<날짜>.40.BIO.<도메인>KM_nctox.ncf`로 이름 붙여 SMOKE 출력 폴더에 복사 |
| 3·1km (영남권·부산권) | BEIS 3.12 (SMOKE 2.7 내부) | 임상도·토지피복도 → BELD3, BEIS3 배출계수표(`b3fac_beis3_efac_v0_98.txt`, `beis3_efac_v3_14_16may2008_v0`, 230종) | SMOKE 안에서 자연오염원으로 계산 → Mrggrid의 BIO |

**근거:** 기존 시스템 소개 자료의 모델·해상도 표와 MEGAN/BEIS 도식(사용자 제공), FNL 체계 실행 스크립트 `eni_new_megan_run.csh`(realtime_fnl_cmaq 설정 사용본)와 `setcase`, MEGAN Input 폴더 파일, BEIS 입력 파일, 「대기질 진단·평가 시스템 고도화 개발 보고서」(2017.12, 프로그램 목록에 GFS·UM·FNL 체계별 "MEGAN 모델 수행" 작업 포함).

**확인 중 발견한 특이사항 (재사용하지 않으므로 기록만 함):**

- MEGAN `EF1` 입력은 이소프렌(ISOP)만 격자별 값(최대 약 1.2만)이 있고 나머지 19종 배출계수는 전 격자 1로 고정되어 있다. 도식에 표시된 10종 배출계수 지도와 다르다.
- `D_SRAD`(300), `D_TEMP`(293)는 전 격자 고정값, `TZONE`은 전 격자 0(GMT)이다.
- FNL 실행 스크립트는 MEGAN을 27·09·03·01 네 도메인 모두 반복하도록 되어 있으나, MEGAN 입력은 27·09KM만 확인되었다. 스크립트 중간의 `exit` 뒤 SMOKE 실행 부분(북한·면·점·bio·merge)은 실행되지 않는 남은 코드다.
- BEIS용 `bgpro_wrf2_03KM`(83×83), `bgpro_wrf2_01KM`(78×70)은 한 지역코드를 전 격자에 균등 배분한 형식용 대리자료이며, 실제 식생 정보는 BELD3 격자 파일에 있다(02 §7).

### 9.2 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 생물성 모델 | **CMAQ 5.5 CCTM 인라인 MEGAN 3.2** | CMAQ 5.4부터 CCTM에 내장되어 실행 중 계산. 전 지구 자료로 입력을 만들 수 있어 동아시아~부산 전 영역에 적용 가능. BEIS4가 쓰는 BELD 토지이용 자료는 미국 중심 |
| 적용 도메인 | 27·09·03·01KM **4개 도메인 공통** | 기존처럼 도메인별로 모델을 나누면 중첩 경계에서 배출량 수준 차이가 생길 수 있음 |
| 토양 NO | **YL95**(Yienger and Levy 1995, MEGAN 기본) | 현재 WRF 지표모델이 Noah(`sf_surface_physics = 2, 2, 2, 2`, [WRF/WPS 가이드](../wrf/WRF_WPS_Installation_Guide.md))이고, BDSNP는 PX 지표모델을 전제로 함. 기존 WRF 설정·검증 결과를 그대로 유지 |
| SMOKE 생물성 부문 | **실행하지 않음** (`normbeis4`·`tmpbeis4` 미사용) | 생물성은 CCTM 안에서 더해지므로 SMOKE 병합은 국내+국외 인위 배출만 대상 |
| 기존 입력 | MEGAN v2.04·BEIS3 입력은 **재사용하지 않음** | 결과 비교용 참고자료로만 보존 |

**보류한 대안:** WRF를 PX 지표모델(`sf_surface_physics = 7`)과 짝 설정으로 바꾸고 BDSNP를 쓰는 방안은 기상 체계 전체를 바꾸는 결정이므로, 기상 설정 개선 검토 시 별도로 판단한다.

### 9.3 CCTM 실행 시 설정 (예정, 미실행)

실행 변수는 CMAQ 기준 태그 `CMAQv5.5.0.3_11Jul2025` (`e10d0a0`)의 [소스](https://github.com/USEPA/CMAQ/blob/e10d0a0/CCTM/src/util/util/RUNTIME_VARS.F#L831)와 [CB6R5 예제 스크립트](https://github.com/USEPA/CMAQ/blob/e10d0a0/CCTM/scripts/run_cctm_Bench_2018_12NE3_CB6R5.csh#L174)를 따른다. 부산 실행 로그에서 적용된 설정을 확인한다.

| 변수 | 설정 | 비고 |
|---|---|---|
| `CTM_BIOGEMIS_MG` | `Y` | MEGAN 인라인 계산 사용 |
| `CTM_BIOGEMIS_BE` | `N` | 소스 기본값은 `N`. 공식 예제 스크립트는 `Y`로 설정하므로 부산 실행에서 명시적으로 `N`을 지정 |
| `BDSNP_MEGAN` | `N` | 토양 NO를 YL95로 계산(기본값) |
| `MEGAN_CTS`, `MEGAN_EFS`, `MEGAN_LDF` | 도메인별 파일 경로 | MEGAN 전처리기로 생성하는 캐노피·배출계수·광의존 비율 파일 |
| `USE_MEGAN_LAI` | `N`(기본) | 기본은 CMAQ의 다른 과정과 같은 LAI를 사용. 별도 LAI 사용 여부는 §9.5 |
| `NOAH_VERSION` / `PX_VERSION` | `Y` / `N` | 기상 지표모델 표시. MCIP `METCRO2D`의 `SOIM1`, `SOIT1`, `SLTYP` 등 토양 필드 확인 |
| `MEGAN_SOILOUT` / `MEGAN_SOILINP` | 도메인·날짜별 경로 | 같은 도메인의 전날 출력 파일을 다음 날 입력으로 사용 |
| `IGNORE_SOILINP` | `N` (기본) | 정상 연속 실행에서는 `N` 유지. `Y`는 전날 상태 없이 재초기화할 때만 사용하고 실행 기록에 남김 |

**이중계상 확인.** SMOKE 병합 목록에는 국내 점·면·이동·바다와 해당 도메인의 HTAP 부문만 넣는다. HTAP은 27·09·03KM에 적용한다. 기존 `b3gts*BIO*`, 오프라인 MEGAN 산출물, 생물성이 포함된 예제 또는 과거 병합 파일이 병합 목록과 CCTM 입력 스트림에 없는지 파일의 생성 이력까지 확인한다. CCTM 시작 로그와 DESID 스트림 진단에서 인라인 MEGAN만 생물성 배출을 공급하는지 확인한다.

### 9.4 입력 준비 (예정, 미실행)

[UCI MEGAN 자료·코드 페이지](https://bai.ess.uci.edu/megan/data-and-code)의 MEGAN 전처리기로 4개 도메인(GRIDDESC `EASTASIA`의 27KM·09KM·03KM·01KM) 입력 파일을 만든다. 설치·생성 명령과 입력 자료 연도는 실제 실행으로 확인한 뒤 CCTM 단계 문서(기본계획의 생물성 산출물)에 기록한다.

생성 후 각 파일의 투영·원점·격자 간격·행열을 해당 MCIP `GRIDDESC`와 대조한다. Noah 기반 MCIP의 토양수분·토양온도·토양 유형·강수·LAI를 해당 CCTM 빌드가 읽는지 확인한다. 화학 메커니즘을 확정한 뒤 SMOKE 배출종·단위·DESID와 MEGAN의 메커니즘별 `.EXT` 매핑을 대조한다. 도메인별 이틀 연속 시험에서 초기화, 전날 `MEGAN_SOILOUT`을 사용한 재시작, 이소프렌과 토양 NO 배출 진단을 확인하고 로그·파일 목록을 기록한다.
