# CMAQ 운영 문서: 설치와 Case 실행 분리

> 문서 기준: 2026-11-16. **이 페이지는 기존 검증 문서로 이동하는 운영 목차**이다. 실제 프로그램 명령과 파일 내용은 각 원문을 우선한다. 문서 구조 개편 자체는 모델 재실행이나 검증을 뜻하지 않는다.

## 1. 어느 문서부터 읽어야 하나?

| 목적 | 읽을 문서 | 실행 시점 |
|---|---|---|
| 새 Linux 장비에 재구축 | [설치·컴파일 안내](INSTALLATION_INDEX.md) | 최초 구축, 버전·라이브러리·패치 변경 시 |
| 기상 Case 변경 | [WRF/WPS 반복 실행](WRF_WPS_CASE_RUN.md) | 새 기간·격자·기상 설정 |
| CMAQ 기상장 생성 | [MCIP 반복 실행](MCIP_CASE_RUN.md) | WRF 출력·기간·영역 변화 |
| 국내/국외/식생 배출량 | [배출량 반복 실행](EMISSIONS_CASE_RUN.md) | 배출 인벤토리·기간·영역·시나리오 변경 |

**설치·컴파일된 공통 바이너리는 Case마다 다시 빌드하지 않는다.** 다만 소스 패치, 빌드 설정·화학기작·라이브러리 ABI를 바꿨다면 적절한 범위의 재컴파일과 검증이 필요하다.

## 3. Case 변경 시 재실행 결정

1. **변경 입력 확인**: 기간(UTC), WRF domain/grid, 기상자료, 배출원·기준연도, 시간·화학종 프로파일, MEGAN 입력, CCTM 화학기작·IC/BC·태그를 기록한다.
2. **입력 의존성 확인**: 기존 산출물의 날짜·영역·수직층·화학종·파일 내용이 새 Case와 동일하면 재사용할 수 있다. 단순 파일 존재만으로 재사용 판정하지 않는다.
3. **최초 영향 단계부터 재실행**: 기상변경은 필요한 WPS/WRF → MCIP, 그 기상자료에 의존하는 SMOKE/MEGAN 처리 → CCTM; 배출량만 변경한 경우 해당 부문 전처리 → 병합 → CCTM. 태깅·IC/BC 변경 시 관련 CCTM/ISAM 입력을 다시 만든다.
4. **이전 결과 격리**: 실행 전 기존 결과·로그를 백업해 새 실행과 섞이지 않게 한다. 원문에서 삭제 명령을 실행하기 전 반드시 Case 경로 확인.
5. **완료 검사**: 정상 종료 메시지, 요청 시각 범위, GRID/ROWS/COLS/LAYS, 배출 종 및 단위, 합계·음수/결측·중복 계상 여부를 검증한다.

| 무엇을 바꿨나 | 가장 앞서 확인할 실행 단계 | 참고 |
|---|---|---|
| 분석 날짜만 바뀜 | 필요한 FNL/WPS/WRF 데이터 확보부터; 기존 기상파일이 해당 기간을 완전히 포함하면 재사용 검토 | 기간만 바뀌었다고 무조건 WRF 재실행하지 않음 |
| WRF 물리 설정·입력기상 변경 | WRF, 필요 시 WPS → MCIP → 기상 의존 배출 전처리 → CCTM | physics 옵션에 따라 추가 runtime 테이블 필요 |
| 도메인·격자 변경 | WPS geogrid부터 재검토 → WRF/MCIP → 공간할당·MEGAN 입력 → CCTM | 모든 GRIDDESC 일치 확인 |
| CAPSS 원자료·배출계수 변경 | 국내 입력 생성/SMOKE 해당 부문부터 | 다른 부문은 입력 불변이면 유지 |
| HTAP 원자료·마스킹·프로파일 변경 | 국외 생성기/해당 8묶음부터 | SMOKE 패치는 최초 설치 또는 소스 교체 때만 |
| MEGAN CT3·EFMAP·LDF 변경 | MEGAN 입력 생성부터 | CCTM 연계는 아직 미검증 |
| 후처리 코드만 변경 | 후처리만 | 모델 산출물 불변 전제 |

## 5. 원칙

- 원래 매뉴얼은 보존한다. 이 폴더는 **설치/Case를 가르는 바로가기와 실행 의사결정 계층**이다.
- 검증되지 않은 CCTM·ISAM 명령은 성공한 실행문서처럼 작성하지 않는다.
- 단계별 실제 명령어는 연결된 원문의 코드 블록을 그대로 확인한다.
